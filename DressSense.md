# DRESS SENSE — AI Fashion Advisor

### Your Personal AI Stylist — On-Device, Privacy-First

---

## PROJECT OVERVIEW

Build a fully on-device AI-powered mobile application called **Dress Sense** — a personal fashion advisor that helps users make confident style decisions. Think of it as a personal stylist in your pocket, powered entirely by local AI models running on your phone — no cloud, no internet required, no privacy trade-offs.

The app allows users to upload photos of their own wardrobe items (shirts, trousers, shoes, accessories), take a selfie for skin tone analysis, and get intelligent recommendations on what to wear, what to buy, and whether new items match their personal style. It covers everything from daily outfit planning to shopping decision support.

The app should feel premium, fashion-forward, and trustworthy. The brand palette should be clean and confident — think soft whites, warm beiges, muted golds, with thoughtful typography. Reference the aesthetic of luxury fashion lookbooks and modern style apps.

---

## TECH STACK

- **Frontend**: Flutter (cross-platform iOS + Android) (Dart)
- **On-Device ML Runtime**: `tflite_flutter` (TensorFlow Lite) for all vision models
- **Local LLM**: `flutter_llm` (MLC AI) for running small quantized LLMs (Gemma 2B / Phi-3 / Qwen2.5 1.5B) for natural language fashion reasoning
- **Image Processing**: `image` (Dart), OpenCV (via native bridge if needed), `palette_generator`
- **Camera/Gallery**: `image_picker`, `camera`
- **State Management**: Riverpod or Bloc
- **Local Storage**: Hive / Isar (structured data), `image_picker` cache for wardrobe images
- **On-Device Database**: Drift (SQLite) for wardrobe catalog, preferences, history
- **Background Removal**: `rembg_flutter` or custom tflite MODNet model
- **Face Detection**: MediaPipe Face Mesh (via `google_mlkit_face_detection`)
- **No Cloud Dependency**: 100% on-device. Zero API calls. Privacy guaranteed.

## CORE AI MODELS

### Skin Tone Analyzer

- **Input**: User selfie (front camera)
- **Model**: MediaPipe Face Mesh → extract face region → custom CNN classifier (quantized tflite)
- **Output**: Skin tone category (Deep / Medium / Fair) + Undertone (Warm / Cool / Neutral) + 12-season color type (Light Summer, Deep Autumn, etc.)
- **Size**: ~8MB
- **Performance**: < 500ms inference on modern phones

### Garment Segmenter

- **Input**: User-uploaded clothing image
- **Model**: YOLOv8-nano / MODNet (quantized tflite)
- **Output**: Segmented garment mask + isolated item on transparent background
- **Size**: ~12MB
- **Performance**: < 1s inference

### Garment Classifier

- **Input**: Cropped garment image (post-segmentation)
- **Model**: MobileNetV3-Small (quantized tflite)
- **Classes**: Shirt, T-Shirt, Trouser, Jeans, Shorts, Kurti, Saree, Dress, Skirt, Blazer, Shoes, Sneakers, Sandals, Watch, Chain, Sunglasses, Hat, Bag, Belt, Tie, Scarf, Jacket, Sweater, Blouse, Dupatta, Sherwani, Nehru Jacket, Lehenga, Dhoti, Traditional, Other
- **Size**: ~4MB
- **Performance**: < 200ms inference

### Color Extractor

- **Input**: Segmented garment image
- **Implementation**: Custom logic using k-means clustering + palette_generator
- **Output**: Dominant color (hex), color palette (top 5 colors), HSV/LAB values
- **Performance**: < 100ms

### Outfit Compatibility Engine

- **Input**: Two or more garment images + their classifications + color data
- **Model**: Lightweight embedding model (CLIP tiny variant / custom Siamese network) + rule-based color harmony scoring
- **Rules**:
  - Color harmony (complementary, analogous, triad, monochromatic — scored algorithmically)
  - Style coherence (formal + formal, casual + casual, traditional + traditional)
  - Season appropriateness (summer fabrics, winter layers — rule-based)
  - Skin tone match (warm/cool compatibility with dominant colors)
- **Output**: Compatibility score (0–100), explanation sentences generated by local LLM
- **Size**: ~15MB
- **Performance**: < 2s on-device

### Local LLM (Fashion Reasoning)

- **Input**: Prompt with user context (skin tone, occasion, items being considered, color data)
- **Model**: Gemma 2B / Phi-3-mini / Qwen2.5 1.5B (4-bit quantized, via MLC or llama.cpp)
- **Capabilities**:
  - "Does this blue shirt go with these khaki chinos?" → reasoned advice
  - "Suggest accessories for this outfit" → specific recommendations
  - "Is this suitable for a casual office day?" → contextual advice
  - "Should I buy this? I have X, Y, Z in my wardrobe" → purchase decision support
- **Size**: ~1.5–2.5GB (model file; loaded into memory on first use)
- **Performance**: Cold start ~5–15s (model loading), inference ~3–8s per response
- **Note**: Model loading happens once per app session. Subsequent inferences are faster.

## CORE USE CASES

---

### USE CASE 1 — WHAT TO WEAR TODAY

The user opens the app and wants an outfit recommendation.

**Flow**:

1. User selects occasion: Office / Casual Outing / Party / Traditional Event / Date Night / Travel
2. (Optional) User sets mood/weather: Hot / Cold / Rainy / "Feeling bold"
3. App analyzes user's wardrobe inventory (all items stored locally)
4. Compatibility Engine evaluates all possible combinations:
   - Skin tone harmony with each item's dominant colors
   - Style coherence between items
   - Occasion appropriateness (rule-based)
   - Weather suitability
5. Top 3 outfits presented as cards, ranked by score
6. Each card shows: items used, compatibility score, and a short LLM-generated explanation
   - _Example: "Your navy chinos pair well with this light blue linen shirt. The cool tones complement your skin undertone. Add brown loafers for a polished office look."_
7. User can swipe through, tap to view full outfit, tap individual items to inspect

**Output Format**:

```
Outfit #1 — Score: 92/100
  👔 Light Blue Linen Shirt (you own)
  👖 Navy Chinos (you own)
  👞 Brown Loafers (you own)
  ⌚ Silver Watch (you own)
Why: "The cool blue palette works beautifully with your cool undertone. This is a classic office combination — polished yet breathable for warm days."

Outfit #2 — Score: 78/100
  ...
```

---

### USE CASE 2 — SHOPPING ADVISOR

User is at a store (or browsing online), uploads a photo of an item they're considering buying.

**Flow**:

1. User captures/selects image of the item (shirt, shoe, accessory, anything)
2. App segments and classifies the item, extracts dominant colors
3. App analyzes:
   - Does this item match the user's skin tone? (Warm/Cool harmony)
   - Does this item go with existing wardrobe items? (Compatibility Engine scans all user-owned items)
   - Is this appropriate for the user's typical occasions?
4. Result displayed as:
   - **Verdict**: ✅ Recommended / ⚠️ Okay / ❌ Not Recommended
   - **Score**: 0–100
   - **Matches with**: "Goes well with your black blazer and grey trousers"
   - **Alternative suggestion**: "Since you own a similar blue shirt, consider this in olive green — it would add variety to your wardrobe"
   - **LLM advice**: "This textured blazer in charcoal is versatile. It would work for office meetings and evening dinners. Pair with your existing white shirts and dark denim."

**Confidence booster**: User can tap "How will I look?" and see a generated text description of the complete look using their owned items + this new item.

---

### USE CASE 3 — WARDROBE MANAGEMENT

**Add Items**:

- Upload photo → auto-segment → classify → extract color → save to wardrobe
- Manual entry for items without photos
- Organize by category, color, season, occasion
- Mark favorites, set "most worn" tags
- Note purchase date, brand, size (for fit reminders)

**View Wardrobe**:

- Grid view grouped by category (Shirts, Trousers, Shoes, Accessories)
- Filter by: Color, Season, Occasion, Recently Added, Most Worn
- Search by name, category, color (all local)
- Tap item → Full detail view with image, color palette, metadata, and "Find matches" button

**Outfit History**:

- Saved outfits (user can bookmark combinations they liked)
- "What I wore" calendar (track outfits by date)
- Stats: Most worn item, category distribution, color preference trends

### USE CASE 4 — STYLE COACH (Local LLM Q&A)

User can have a natural language conversation with the AI stylist:

- _"I have a wedding next week. What should I wear with my maroon sherwani?"_
- _"Does this watch go with my formal outfits?"_
- _"What colors should I avoid with my skin tone?"_
- _"Suggest a travel capsule wardrobe for a 3-day trip"_
- _"Rate my outfit"_ (user uploads a photo of themselves dressed)

The local LLM, combined with context from the user's wardrobe data and skin tone profile, generates personalized advice — all on-device.

- **Typography**: Elegant and readable. Suggested: `Playfair Display` for headings, `Inter` or `DM Sans` for body text.
- **UI feel**: Premium cards with generous whitespace. Subtle shadows. High-quality image presentation (garments shown full-bleed in cards). Smooth page transitions.
- **Photography**: All UI mockups and placeholders should use professional flat-lay style fashion photography — garments on clean backgrounds, natural lighting.
- **Logo**: A stylized hanger or mirror silhouette combined with "DS" monogram.
- **Tone of copy**: Warm, encouraging, trustworthy. "Dress with confidence." "Your style, your rules." "Private by design."

## PRIVACY & DATA

This is a core differentiator:

- **Zero data leaves the device**: All AI inference happens on-device via tflite and local LLM
- **No internet required**: Full functionality in airplane mode
- **No account required**: No emails, no passwords, no phone numbers
- **No analytics SDKs**: No telemetry, no usage tracking
- **Camera access only**: For capturing selfie and clothing photos; no continuous background access
- **Photo library access**: Only when user explicitly picks an image; no library scanning
- **Open source models**: All models are publicly available, verifiable, auditable
- **Future cloud features**: If cloud backup is ever added, it must be end-to-end encrypted with user-held keys

**Privacy-first is not a feature — it's the architecture.**

## SUMMARY OF KEY RULES TO IMPLEMENT

1. All AI inference runs on-device. Zero network calls for analysis features.
2. Skin tone analysis requires explicit camera permission with clear explanation.
3. Onboarding skin tone step allows both camera capture and manual selection.
4. At least 1 style preference, 1 occasion, and 1 preferred color must be selected in Step 3.
5. Wardrobe items auto-segment, auto-classify, and auto-extract color on upload — no manual tagging required.
6. Outfit recommendations consider: skin tone harmony, style coherence, occasion fit, weather (if available), and color theory.
7. Shopping Advisor verdict: Recommended / Okay / Not Recommended with explanation.
8. Style Coach (local LLM) has access to user's wardrobe summary and skin tone profile as system context.
9. Free tier caps: 50 wardrobe items, 10 saved outfits, 10 Style Coach queries/day.
10. Pro tier unlocks unlimited items, unlimited queries, outfit calendar, analytics.
11. No internet permission required for core functionality.
12. All user data stored in local SQLite database. No sync. No cloud.
